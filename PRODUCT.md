# autopost-core как продукт: требования Meta и план

Записано 12.11.2026 по итогам обсуждения. Требования Meta меняются — перед подачей
на проверку сверить с актуальной документацией developers.facebook.com.

## Где мы сейчас

- Приложение Meta `autopost-dev` в **режиме разработки**, подключено бизнес-портфолио Axis group.
- Вход: **API setup with Unified login** (вход через Instagram для новых приложений Meta больше не даёт),
  конфигурация «Instagram API (единый вход)» из шаблона, токен системного пользователя.
- Ядро уже поддерживает **много аккаунтов**: свои слоты, квоты и статусы у каждого,
  один пост можно отправить в несколько аккаунтов (`targets`).
- Подключать сейчас можно только аккаунты, добавленные **тестировщиками Instagram** в приложении:
  1. аккаунт профессиональный (Business/Creator);
  2. «Роли в приложении → Добавить людей → Тестировщик Instagram» и принять приглашение
     на instagram.com/accounts/manage_access;
  3. «API setup with Unified login → Сгенерировать маркер» → вставить в ядро.

## Почему не «логин и пароль от Instagram»

Собирать пароли от Instagram нельзя:

- нарушение Meta Platform Terms и правил Instagram — блокируют и аккаунты, и приложение;
- вход с чужого сервера вызывает проверки, 2FA и временные блокировки — автопостинг постоянно ломается;
- хранить чужие пароли — риск утечки самих аккаунтов.

Неофициальные библиотеки (instagrapi и т. п.) так работают, но живут до первой блокировки.

**Правильный путь — OAuth:** кнопка «Подключить Instagram» → страница входа Meta (логин и пароль
пользователь вводит там) → «Разрешить» → возврат в ядро с токеном. Пароль мы не видим и не храним,
доступ отзывается в настройках Instagram. Так работают Buffer, Later, Metricool, Postiz.

| Этап | Кто может подключаться | Что нужно |
|---|---|---|
| Режим разработки | Только аккаунты-тестировщики | OAuth в ядре + redirect URI `https://post.dkmatrix.com/…/callback` в приложении Meta |
| Live | Любые пользователи | Всё, что ниже: верификация бизнеса, App Review, страницы privacy/terms |

## Требования Meta для продукта

### 1. Компания

- **Business Verification** бизнес-портфолио в Meta Business Suite: юрлицо, документы о регистрации,
  совпадающие название и адрес, подтверждённый домен или телефон.
- **Статус Tech Provider** («Стать поставщиком технологий» на панели приложения) — нужен,
  чтобы подать App Review и получать доступ к данным других бизнесов.

### 2. Настройки приложения (Live mode)

- Политика конфиденциальности — публичная страница (например, `post.dkmatrix.com/privacy`).
- Условия использования — публичная страница.
- Удаление данных — инструкция или callback.
- Иконка 1024×1024, категория, контактный email, домены приложения.
- Перевод приложения в **Live**.

### 3. App Review — Advanced Access

Минимум:
- `instagram_business_basic` — профиль аккаунта;
- `instagram_business_content_publish` — публикация.

Позже по мере функций: комментарии (первый комментарий), insights (аналитика).

Для каждого разрешения:
- конкретное описание, зачем оно нужно;
- **screencast полного сценария**: вход через Meta → подключение → создание поста → пост в Instagram;
- тестовый доступ для проверяющих (логин в ядро и тестовый IG-аккаунт).

Частые причины отказа: видео без полного пути, лишние разрешения, приложение не работает
у проверяющего, нет privacy policy. Срок — от нескольких дней до пары недель, часто со второй попытки.

### 4. Постоянные обязательства

- **Data Use Checkup** раз в год.
- **Data Protection Assessment** для части разрешений (анкета о хранении и защите данных).
- Соблюдение Platform Terms: не продавать данные, удалять по запросу, не публиковать без действия пользователя.
- Ограничения API остаются: только профессиональные аккаунты, 100 публикаций в сутки на аккаунт.

## Что доделать в ядре

| Что | Зачем |
|---|---|
| OAuth «Подключить Instagram» | Обязательно для чужих аккаунтов |
| Регистрация и личные кабинеты | Пользователи и изоляция данных (workspaces уже есть в схеме БД) |
| Обработка отключения (webhook deauthorize) | Пользователь отозвал доступ в Instagram |
| Страницы privacy, terms, удаление данных | Требование Meta |
| Автопродление токенов | Пользовательские токены живут ~60 дней |
| Тарифы и оплата | Если продукт платный |

## Риски

- **Россия.** Meta признана в РФ экстремистской организацией (2022), Instagram заблокирован.
  Коммерческий продукт на API Meta для российского юрлица и российских клиентов может нести
  юридические риски — **нужна консультация юриста**. Для компании и клиентов вне РФ вопроса нет.
- **GDPR.** Сервер в Германии (Netcup) и европейские пользователи → нужно соответствие GDPR
  (политика, удаление данных, договор обработки данных при необходимости).

## TikTok при продуктовом подходе

Аудит TikTok Content Posting API не одобряет инструменты «для своих аккаунтов»,
но продукт для многих авторов — ровно тот сценарий, под который аудит сделан.
Путь к публичным постам (а не только SELF_ONLY) открывается.

## Цены: ориентиры рынка

Примерные цены конкурентов (по памяти, сверить перед запуском):

| Сервис | Модель | Порядок цен |
|---|---|---|
| Buffer | за канал в месяц | ~$5–10 за канал |
| Later, Metricool | тарифы по числу аккаунтов | ~$20–50/мес, есть бесплатные планы |
| Postiz Cloud | тарифы | ~$29+/мес |
| SMMplanner, Onlypult (RU-рынок) | тарифы | ~500–3000 ₽/мес |
| Mixpost Pro | разовая лицензия self-hosted | ~$300+ разово |

Вывод: **просто планировщик — товар с низкой ценой** (~$5–15 за аккаунт). Дороже продаётся
**«контент на автопилоте»**: генерация постов по нише (таро/эзотерика, авто/запчасти) + автопостинг —
ориентир $30–100+/мес за аккаунт или бренд. Себестоимость низкая: весь стек ~260 МБ RAM,
дополнительный аккаунт почти ничего не стоит, основная статья — генерация (AI, рендер видео).

## Порядок и сроки

1. Business Verification + статус Tech Provider.
2. OAuth, кабинеты пользователей, автопродление токенов в ядре.
3. Страницы privacy, terms, удаление данных.
4. Screencast и App Review.
5. Live mode.

Реалистично **1–2 месяца** с учётом ожидания проверок.
